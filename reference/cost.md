# 成本速查

一次调用花多少钱，只有三个变量：**输入 token、输出 token、单价。**

麻烦的是 token 数你看不到，单价各家不同且会变。这张表解决前一个问题，后一个问题只能查账单。

## 一、单价怎么读

厂商报价通常是「元 / 百万 token」：

```
输入：2 元 / 百万 token   → 1 个 token = 0.000002 元
输出：8 元 / 百万 token   → 1 个 token = 0.000008 元
```

**所以 `cost = 输入token × 输入单价 + 输出token × 输出单价`，注意单位都是「百万」。**

本书示例统一用**微元（micros，百万分之一元）**做整数存储：

```java
long costMicros = Math.round(promptTokens * inPrice + completionTokens * outPrice);
```

因为 `inPrice` 的单位是元/百万 token，`tokens × 单价` 的结果**正好就是微元** —— 这个等式能省掉全部精度烦恼（第 8 章踩过 `0.0007` 被四舍五入成 `0.0` 的坑）。

## 二、token 怎么估（看不到 usage 时）

| 语言 | 粗略比例 | 说明 |
| --- | --- | --- |
| 中文 | 1 token ≈ 1.6–1.8 个汉字 | 本书用 `len / 1.75` |
| 英文 | 1 token ≈ 4 个字符 | 常用词更省 |
| 代码 | 1 token ≈ 3 个字符 | 符号多，更费 |

```java
static int estimateTokens(String text) {
    return Math.max(1, (int) Math.round(text.length() / 1.75));
}
```

**这只是兜底。** 流式调用要显式要求返回 usage（`stream_options.include_usage`），否则实测偏低 **12.6%**（第 8 章：估算 139，真实 159）。

## 三、每千次调用要多少钱

按「示例单价」算，只看量级：

| 场景 | 输入 token | 输出 token | 单次成本 | 1000 次 |
| --- | --- | --- | --- | --- |
| 短分类 | 120 | 5 | 0.0003 元 | 0.28 元 |
| 工单生成（带 2 段资料） | 1200 | 200 | 0.0040 元 | 4.0 元 |
| 长文档摘要 | 8000 | 800 | 0.0224 元 | 22.4 元 |
| 多轮客服（10 轮） | 6000 | 1500 | 0.0240 元 | 24.0 元 |

> 单价是示例值，不是任何厂商的真实报价。换单价时代入公式即可。

**注意最后两行的对比**：长文档摘要是 8 倍于工单的输入，成本 5.6 倍；而 10 轮客服的输入里**大部分是重复的历史**，这就是为什么"多轮便宜"是个错觉。

## 四、三个能立刻降成本的开关

| 开关 | 典型收益 | 代价 |
| --- | --- | --- |
| 前缀缓存 | 输入成本 −20% 上下（实测 21%） | 前缀必须逐字节相同，且放最前 |
| 分类用小模型 | 该环节 −70% 左右 | 质量下降，需评测 |
| 截断历史 | 取决于对话长度 | 长对话会丢上下文 |

**最有效的其实是第四个，但它不是参数**：减少不必要的调用。工单示例里 6 次调用中，2 次是分类、4 次是生成 —— 分类只占 6% 成本却占 1/3 的调用次数，**先优化调用次数，再优化单价**。

## 五、成本观测的最小字段

一条调用明细，至少要记这些，否则事后无法归因：

| 字段 | 用途 |
| --- | --- |
| `trace_id` | 串起一次业务请求的所有调用 |
| `tenant` / `user` | 谁花的钱 |
| `provider` + `model` | 哪个模型花的 |
| `prompt_tokens` / `completion_tokens` | 结构 |
| `cost_micros` | 金额（整数） |
| `latency_ms` | 顺带的性能数据 |
| `estimated` | 这个 token 数是估的还是上游给的 |

最后一个是本书加的：**不标出来，你永远不知道那 12.6% 的偏差存在。**

## 六、速算口诀

```
输入成本 ≈ 字数 / 1.75 × 输入单价
输出成本 ≈ 字数 / 1.75 × 输出单价
总成本   ≈ 字数 × (单价之和) / 1.75
```

举例：1000 字的中文 prompt，输入单价 2 元/百万：

```
1000 / 1.75 ≈ 571 token
571 × 0.000002 元 ≈ 0.0011 元
```

**一厘钱。** 所以"贵不贵"从来不取决于单次，取决于量和使用方式。
