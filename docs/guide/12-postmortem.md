# 第 12 章 · 生产事故复盘集

::: info 本章状态：已规划（仅提纲）
下面是完整提纲。想优先看到这一章？[开个 Issue](https://github.com/pgy763/hello-ai-backend/issues) 说清你的场景，我按热度排优先级。

## 这一章解决什么问题

前面 11 章讲的都是「怎么搭对」。这一章讲「搭对了也会怎么炸」—— 全部来自真实故障，不是想象的场景。

每一篇的结构都一样：**现象 → 根因 → 止血 → 根治 → 怎么提前发现**。

## 计划收录的复盘

| # | 事故 | 一句话教训 |
| --- | --- | --- |
| 1 | 密钥进了 git 历史 | 删掉当前代码没用，`git log -S "sk-"` 有输出就说明已经泄漏了 |
| 2 | 一个死循环刷掉一个月预算 | 没有限流 + 没有重试上限 = 无限计费 |
| 3 | 降级链把好请求也降级了 | 健康判断太敏感，一次抖动就让全站走了低质量模型 |
| 4 | 任务永远卡在「处理中」 | 非终态没有超时回收，僵尸任务堆积 |
| 5 | 升级框架后流式静默失效 | 接口还能返回，只是不再流式了 —— 没有回归测试就发现不了 |
| 6 | 并发下额度超发 | 检查与扣减不是原子的，压测时才发现 |
| 7 | Windows 下中文全部乱码 | 编码问题不影响功能，但会让用户投诉 |

> 编号只是占位，实际收录顺序按严重程度排。**欢迎把你的事故开 Issue 投过来** —— 别人的事故比自己的便宜。
