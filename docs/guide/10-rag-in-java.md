# 第 10 章 · 把 RAG 接进 Java 服务

## 这一章解决什么问题

上一章让检索跑通了。这一章要让它**长期跑下去**：数据每天在变，索引怎么跟上，失败的文档怎么重试，重跑时怎么不重复写入。

## 你会得到

- 一条能持续运行的索引流水线（不是一次性脚本）
- 增量更新策略：新增、修改、删除三种情况分别怎么处理
- 检索环节接进现有 Spring 服务的方式，与第 3 章 Provider 抽象的对接

## 提纲

- **10.1 一次性脚本和流水线的差距** —— 失败重试、进度记录、限流、可观测
- **10.2 文档变更的三种情况** —— 新增、修改、删除，各自的处理成本
- **10.3 增量索引** —— 用什么标记「已经索引过」，为什么时间戳不够
- **10.4 文档切分与元数据** —— 元数据决定你能不能按权限过滤，别事后补
- **10.5 检索结果怎么进 Prompt** —— 排版、截断、引用编号
- **10.6 权限过滤** —— 不同用户能看到不同文档，这一步做错就是数据事故
- **10.7 索引失败的兜底** —— 死信、重试上限、人工介入入口
- **10.8 结论** —— 一条最小可用的流水线长什么样
