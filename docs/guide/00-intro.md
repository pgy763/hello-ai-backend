# 序章 · 写给谁，以及为什么不是 Python 教程

## 一个很常见的一周

**周一**，老板说：我们的客服系统，能不能加个 AI 自动回复。

**周二**，你打开了 Spring AI 的文档。

**周三**，你跑通了第一个 demo —— `ChatClient` 老老实实返回了一句话。你把截图发到群里，群里回了一排点赞。

**周四**，你准备把它接到生产环境。然后真正的问题开始了。

生产环境要的，从来不是「能返回一句话」：

- 我们有三条业务线要用这个模型，额度怎么分？月底账单算到谁头上？
- 主模型上周日挂了 40 分钟，客服系统跟着一起挂 —— 这能接受吗？
- 用户点一次「生成」要等 12 秒，前端转圈圈转到用户关页面
- 一个「分析这批工单」的任务要跑 20 分钟，中途服务重启，全丢了，得从头再来
- 月底老板问：这个月 AI 花了多少钱？你答不上来

**这些，才是这本书要讲的。**

## 为什么现有资料不够

市面上关于 AI 应用的资料，大致分三类，覆盖的东西各不相同：

| 资料类型 | 讲什么 | 不覆盖什么 |
| --- | --- | --- |
| 官方文档（Spring AI / LangChain4j） | API 怎么调、接口有哪些参数 | 生产环境的多租户、降级、成本核算 |
| 入门教程与视频课 | 概念、Quick Start、demo 项目 | 真实流量下的限流、熔断、可观测性 |
| 工程博客与事故复盘 | 某个具体问题的解法 | 不成体系，互相之间不衔接 |

这三类都有价值，但它们之间有一道缝：**从「能调通 API」到「能上生产」之间的那一段，几乎没人系统地写。**

而这一段，恰好是 Java 后端工程师最擅长、也最应该负责的部分。

## 这本书不讲的

先把边界划清楚，免得你读到最后觉得被骗：

- **不讲** Transformer 原理、注意力机制的数学推导 —— 那不该由后端工程师负责
- **不讲** 怎么训练、微调模型 —— 那是算法团队的活
- **不讲** Prompt 工程的十八般技巧 —— 有更好的专门资料
- **不讲** Dify / Coze 这类低代码平台怎么拖拽 —— 那是另一种技术路线

这本书只做一件事：**把一个已经上线的 Java 后端系统，从「能调 API」推到「能上生产」。**

## 这本书要造的东西

全书围绕一个东西展开，叫 **AI 接入层**。它夹在业务系统和模型厂商中间，负责那些「业务不该关心、厂商不负责」的事：

```
  业务系统               AI 接入层                 模型厂商
┌────────────┐      ┌──────────────────┐      ┌────────────┐
│  客服系统   │      │   虚拟密钥 / 额度  │      │  模型 A     │
│  博客后台   │ ───▶ │   路由 / 降级链    │ ───▶ │  模型 B     │
│  数据分析台 │      │   熔断 / 限流      │      │  模型 C     │
└────────────┘      │   任务编排         │      └────────────┘
                    │   计量 / 成本核算   │
                    └──────────────────┘
```

业务系统只管说「我要一段回复」，剩下的路由到哪个厂商、超了怎么办、花了多少钱，全由接入层兜住。

**你要有耐心的话，读完这本书，就有一个能上生产的接入层了。**

## 怎么读

**推荐路径** —— 如果你不赶时间：

```

     → 4 → 5 → 6 → 7 → 8  ② 补上生产机制（核心）
     → 9 → 10             ③ 让 AI 读懂你自己的数据
     → 11 → 12 → 13       ④ 上线，然后去面试
```

**赶时间路径** —— 如果你只有一天，明天就要给老板一个答复：

```
序章 → 第 1 章（选型决策表）→ 第 5 章（降级）→ 第 8 章（计量）
```

**已经在做 AI 项目的人** —— 直接跳第 5、6、7、8 章。这四章是市面资料最缺的部分，也是线上最容易出事的四块。

## 你需要什么

- **Java 基础**：会用 Spring Boot 写 Controller 和 Service 就够了，不需要懂 AI
- **一台能跑 MySQL 和 Redis 的机器**：本地 Docker 也行
- **一个大模型 API Key**：不一定非要 OpenAI。全书都以 **OpenAI 兼容协议**为准，DeepSeek、通义、智谱换个 `base_url` 和模型名就能跑

> 如果你在 Windows 上跑，可能会先撞上一堆编码、依赖、代理问题。这些作者已经单独整理成了按报错关键词索引的手册：[llm-dev-pitfalls](https://github.com/pgy763/llm-dev-pitfalls)。
