# 第 9 章 · RAG 落地：向量库选型与切分策略

## 这一章解决什么问题

模型不知道你公司内部的东西，所以答非所问。RAG 是解法，但多数人的 RAG 效果很差，而且**不知道为什么差**。

## 你会得到

- 一套向量库选型标准（不只看性能，还看运维成本和解耦能力）
- 一个能解释「为什么答非所问」的排查路径
- 切分策略的取舍表：按长度、按语义、按结构，各自什么时候成立

## 提纲

- **9.1 RAG 的三段流程** —— 索引、检索、生成，问题分别会出在哪一段
- **9.2 向量库选型** —— Redis / pgvector / Milvus / 云托管，按团队规模给结论
- **9.3 换 embedding 模型会怎样** —— 维度不匹配，以及已经建好的索引怎么办
- **9.4 切分策略** —— 切太碎检索不到，切太大噪声淹掉答案
- **9.5 检索质量的排查路径** —— 先确认「检索到没」，再确认「生成对没」
- **9.6 什么时候不该用 RAG** —— 长上下文、结构化查询、精确匹配，各有更合适的方案
- **9.7 结论** —— 一套最小可用的 RAG 参数起点
