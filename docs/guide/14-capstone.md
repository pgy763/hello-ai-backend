## 这一章解决什么问题

前面 13 章的知识，如果不落到一个真实项目上，两周就忘光了。

这一章不给新知识 —— 它给你一个**验收清单**，让你把前面学的东西，全部接到你自己已有的系统上。

## 为什么是「你自己的系统」

因为现成的 demo 项目没有真实约束：没有存量数据、没有历史包袱、没有权限模型、没有「不能停机」的要求。而这些约束，才是工程能力的试金石。

你的博客、你的管理系统、你的课程设计 —— 什么都行，只要它真的在跑。

## 验收清单

**基础层（必须全部完成）**

- [ ] 有一个独立的接入层，业务系统不直接调用模型厂商
- [ ] 虚拟密钥生效：能区分出是哪个业务线发的请求
- [ ] 主模型不可用时，自动切到备用模型，业务无感
- [ ] 有限流，超过阈值时返回明确的错误而不是拖死服务
- [ ] 每次调用都有日志，能算出花了多少钱

**进阶层（做 3 项以上）**

- [ ] 有一个多步任务，支持断点续跑，重启不丢进度
- [ ] 接了一套 RAG，能回答只有你的数据里才有的问题
- [ ] 有一份压测报告，能说出系统在多少并发下开始劣化
- [ ] 成本异常时能收到告警

**收尾（决定这份设计能不能写进简历）**

- [ ] 有一份架构文档，讲清每个模块为什么这么设计
- [ ] 有至少一篇事故复盘，写清你踩的坑和怎么修的
- [ ] 能画出「一次请求的完整旅程」时序图
